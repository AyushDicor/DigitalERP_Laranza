## 2. Environment traps — these WILL bite you

**1. `app_constant.dart` and `app_constant_new.dart` both define the `new*`
colour tokens in Globenex.** (In Balaji only the `_new` file does.) Importing
both unprefixed gives dozens of `ambiguous_import` errors. Fix by hiding the
duplicates on the old import:
```dart
import 'package:digitalerp/utils/app_constant.dart' hide newTextPrimary, newBlueColor;
import 'package:digitalerp/utils/app_constant_new.dart' show newTextPrimary, newBlueColor;
```
This cost ~41 errors when porting the lead module.

**2. `dropdown_button2` is v1.9.4 — the OLD API.** Use
`buttonHeight`, `buttonPadding`, `buttonDecoration`, `dropdownDecoration`,
`dropdownMaxHeight`, `icon`. The newer `buttonStyleData` / `menuItemStyleData`
API **does not compile**.

**3. Always analyze `lib` only:**
```
flutter analyze lib          -> expect 0 errors
flutter analyze              -> ~1285 errors, ALL pre-existing in
                                third_party/camera_android_camerax/example.
                                Ignore them; they are not part of the app build.
```

**4. `yearId` is an ID (`"9"`), not a financial-year label.** Several screens
did `int.parse('${yearId.split('-').first}')` during `build()` — which throws
`FormatException` on null and produced nonsense years. Removed where found;
**more may exist elsewhere in the codebase.** Use `AppConst.calenderFirstDate` /
`calenderLastDate` (2000–2050) for date-picker bounds.

**5. The test device reports its location as Mountain View, California**
(emulator default, 37.42 / -122.08). Any distance/nearby feature returns
meaningless values until a real device or a Raipur location is used.

**6. Shell notes.** PowerShell here has **no `&&`** — use `;` or `if ($?) { }`.
`grep -P` is unsupported. Use the Read/Grep/Edit tools rather than `sed`/`awk`
for edits (a past `awk` trick truncated files to 0 bytes).

**7. Two lead modules now exist.** See section 4 — don't confuse them.

### 3.3 Visit module
- **Hard crash fixed** (this was "I can't add a visit plan"):
  `preview_controller.dart` did `previewVisitDataList.first` **outside** the try
  block → `StateError` on an empty list, killing the app. The Submit button also
  stayed enabled over the "No Data Available" state, so it was fully reachable.
  Guarded + button now disabled when empty.
- **Delete was sending the wrong id.** `deleteVisit` sent `element.partyid`;
  the endpoint expects the **visit-list row id** (3615, 3616…). It matched
  nothing, returned `"Data Deleted"` anyway, and left the record in place — so a
  customer already in the plan could be neither added ("Data Allready Added")
  nor removed. Permanently stuck. Now resolves the real row id.
- **Already-added customers are now pre-ticked.** `VisitCustomerListData.fromJson`
  hardcodes `isChecked: false`, and the customer-list API has no "already added"
  flag, so the screen had no idea. It now calls `Addtovistlist/addtovisitlist` on
  open and ticks matches. **Joined by customer NAME** — there is no shared id
  (see backend asks).
- **Three RenderFlex overflows** — unbounded `Column` inside `Row` in
  `new_visit_planing_view.dart`, `preview/preview_view.dart` and
  `visit_plan_detail_view.dart`. Wrapped in `Expanded` + ellipsis.
- **New Visit Planning filter**: Apply did nothing when only the slider moved
  (a stale null-check on the removed Nearby dropdown); picking a state with no
  cities crashed (`.first` on empty); slider hardcoded to 100 km although the
  master returns 150. All fixed; slider max now comes from the API.
- **All / Pending / Completed tabs** added to the visit list.
  **Note:** the API returns **four** statuses — Completed (777), Pending (153),
  Planned (15), Closed (5). Balaji matches only "pending"/"completed", so Planned
  and Closed fall into neither tab and its counts don't reconcile. In Globenex,
  **Planned → Pending** and **Closed → Completed**. *Balaji still has the gap.*

### 3.4 Add Lead + Lead filter

## 8. Recurring bug patterns in this codebase

Worth grepping for proactively — each has already caused a real failure:

1. **`.first` / `[0]` on a possibly-empty list** → `StateError`. Several were
   outside try blocks, so they crashed the app rather than showing an error.
2. **Unbounded `Column` inside a `Row`** → RenderFlex overflow with long party
   names. Wrap in `Expanded` + `maxLines`/`overflow`.
3. **Decorative widgets that look interactive** (`_DropdownRow`,
   `_FilterDropdown`) — no items, no handler. Check before blaming the backend.
4. **Data fetched into a different controller instance than the screen renders**
   (`init: SomeController()` creates a fresh one).
5. **Wrong id sent to an API** (party id vs row id) — made worse by endpoints
   that report success regardless.
6. **`int.parse` on `yearId` during `build()`** → crashes the whole screen.
7. **Copy-pasted controllers** — e.g. the lead filter bound to
   `ApprovalFilterController`.
8. **Filters that only filter already-loaded data** when the real constraint is
   server-side (payment request date range).
